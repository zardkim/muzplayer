## 0. 지금 상태

- 스마트 재생목록은 이미 있다(`smart.py`, `SmartRulesSheet.vue`, 계획서 16.4).
  - 조건 10종: 장르, 아티스트, 연도 범위, 별점, 좋아요, 재생 횟수, 마지막 재생, 추가된 날, 폴더 종류, 곡 길이.
  - 모두 만족 / 하나라도 만족, 정렬 6종, 최대 500곡.
- 조건은 재생목록마다 `playlists.rules`(JSON)에 들어 있고, **열 때마다** 새로 계산한다.

**불편한 점**

| | 지금 | 문제 |
|---|---|---|
| 만들기 | 빈 조건 편집 화면에서 필드·연산자·값을 직접 고름 | 처음 쓰는 사람은 무엇을 골라야 할지 모름 |
| 여러 값 | 장르 조건 하나에 장르 하나 | "발라드나 R&B, 2010년대, 아이유 제외"처럼 묶으려면 '모두/하나라도'가 섞여야 하는데 못 함 |

| 무작위 목록 | 열 때마다 순서와 곡이 바뀜 | 어제 듣던 목록이 오늘 다름 |
| 사용자 취향 | 재생목록마다 따로 | 내 취향을 한 번 알려 두고 여러 목록에 쓰는 방법이 없음 |

## 1. 마법사 + 사용자별 취향 조건

### 1.1 흐름

`내 플레이리스트 → 스마트 재생목록 만들기` → 마법사(한 화면에 질문 하나, 휴대폰 기준) → 미리보기 → 저장.

| 단계 | 질문 | 고르는 방식 | 미리 채우는 값 |
|---|---|---|---|
| 1 | 어떤 장르를 좋아하세요? | 라이브러리 장르 칩, 여러 개 | 내가 많이 들은 장르 상위 |
| 2 | 즐겨 듣는 가수가 있나요? | 가수 검색 + 칩, 여러 개(건너뛰기 가능) | 내가 많이 들은·좋아요한 가수 상위 |
| 3 | 어느 시대 노래가 좋아요? | 1980·1990·2000·2010·2020년대 칩, 여러 개 / 상관없음 | 없음 |
| 4 | 익숙한 곡과 새로운 곡의 비율은? | 익숙한 곡 위주 / 섞어서 / 새로운 곡 위주 | 섞어서 |
| 5 | 빼고 싶은 것이 있나요? | 장르·가수 칩, 차트·테마 곡 빼기, 최근 N일 안에 들은 곡 빼기, N분 넘는 곡 빼기 | 최근 1일 들은 곡 빼기 |
| 6 | 얼마나 길게? | 곡 수(50·100·200) 또는 재생 시간(1·2·3시간) | 100곡 |
| 7 | 이름과 새로 고침 | 이름(기본: `<아이디>의 스마트 재생목록`), 새로 고침(열 때마다 / 매일 / 매주) | 매일 |

- 각 단계 아래에 **지금 조건에 맞는 곡 수**를 바로 보여 준다(0곡이면 경고).
- 마지막에 곡 미리보기 10곡과 "저장".
- 기존 조건 편집 화면은 '고급 편집'으로 남긴다(마법사로 만든 목록도 열 수 있음).

### 1.2 이름 기본값

- `<아이디>의 스마트 재생목록` (예: `admin의 스마트 재생목록`).
- 같은 이름이 이미 있으면 `… 2`, `… 3`.
- 영어 화면: `<id>'s Smart Playlist`.

### 1.3 저장 구조 (결정 필요 ①)

**A안 — 취향 프로필 1개 + 여기서 만든 목록들 (추천)**

- 사용자마다 취향 조건 하나를 저장한다(새 표 `smart_profiles` 또는 `users.taste` JSON).
- 마법사 1~5단계 = 취향 프로필, 6~7단계 = 목록마다의 설정.
- 프로필을 고치면 그 프로필로 만든 목록이 모두 따라 바뀐다(목록은 `rules.profile = true`로 표시).
- 설정 → '내 취향'에서 언제든 마법사를 다시 열어 고친다.
- 프로필로 서로 다른 목록을 여러 개 만들 수 있다: 같은 취향 + "새로운 곡 위주 50곡", "익숙한 곡 2시간".

**B안 — 목록마다 마법사 답 저장**

- 마법사 답을 그 목록의 `rules.wizard`에 넣고, 다시 열면 그 답으로 마법사가 열린다.
- 단순하지만 "내 취향"을 한 번에 고칠 수 없다.

### 1.4 규칙 엔진 확장 (두 안 공통)

- 여러 값: `genre in [..]`, `genre not_in [..]`, `artist in [아티스트 id..]`, `artist not_in`, `decade in [..]`.
- 묶음: 최상위는 '모두 만족', 그 안의 각 조건이 여러 값 중 하나(위의 `in`)라 대부분의 질문을 표현할 수 있다. 중첩 그룹은 넣지 않는다.
- 익숙함 비율: "익숙한 곡(좋아요·★4 이상·3회 이상 재생)" 과 "새로운 곡(0~1회 재생)"을 비율대로 섞는다(익숙 위주 80:20, 섞어서 50:50, 새로운 곡 위주 20:80). 두 질의를 각각 limit으로 뽑아 섞는다.
- 재생 시간 제한: 곡 길이 합이 N분이 될 때까지(Apple Music의 "시간으로 제한" 방식).
- 기존 목록의 rules는 그대로 읽힌다(새 연산자만 추가).

## 3. 작업 순서 (안)

1. 규칙 엔진 확장(여러 값, 익숙·새로움 비율, 시간 제한, 가수 고르게) + 테스트.
2. 취향 프로필 저장(마이그레이션) + API(`GET/PUT /me/taste`, 장르·가수 추천 값 `GET /me/taste/suggest`, 곡 수 미리보기 `POST /smart/preview`).
3. 마법사 화면(`SmartWizard.vue`), 기본 이름, 설정 → 내 취향.
4. 자동 새로 고침(2-1).
5. 선택한 덧붙일 기능(2-2 ~ 2-6).
6. 스모크 테스트, 화면 확인(휴대폰·PC), 계획서·CHANGELOG.
