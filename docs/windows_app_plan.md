# Windows 앱 계획서 (Electron 클라이언트)

- **작성일:** 2026-11-01 (같은 날 Tauri안 → Electron안으로 변경)
- **상태:** 계획 (구현 전)
- **대상:** Windows 10 21H2 이상 / Windows 11, x64 (ARM64는 2단계)
- **기준 버전:** muzplayer 0.16.x (NAS의 서버·웹 앱)

## 1. 목표와 원칙

NAS의 muzplayer(백엔드와 웹 앱)는 **지금 그대로** 두고, Windows에는 **Electron으로 만든 네이티브 클라이언트 앱**을 설치해 그 서버에 접속한다.

- 서버 쪽 코드·설정·배포 방식은 바꾸지 않는다(앱이 쓰면 좋은 작은 추가만 선택 사항으로, 5장).
- 앱은 서버 주소를 저장해 두고 접속하는 "전용 브라우저 + Windows 기능" 클라이언트다.
- 음악 파일을 PC에 두고 재생하는 로컬 플레이어는 만들지 않는다.

지금도 크롬·엣지의 "앱 설치"(PWA)로 창은 띄울 수 있지만 다음은 안 된다. 이것이 Windows 앱을 만드는 이유다.

| 지금 PWA로 안 되는 것 | Windows 앱에서 |
|---|---|
| 창을 닫으면 음악이 멈춤 | **트레이로 숨기고 계속 재생**, 트레이 메뉴(재생·일시정지·다음·이전·종료), 툴팁에 지금 곡 |
| 다른 앱을 쓰는 중 단축키 | **전역 단축키**(기본 Ctrl+Alt+Space 재생/일시정지, Ctrl+Alt+→/← 다음/이전, 바꿀 수 있음) |
| 작은 창으로 띄워 두기 | **미니 플레이어**(항상 위, 커버·제목·컨트롤) |
| Windows 시작 시 실행 | **자동 시작**(트레이로) |
| 서버 주소가 바뀌면 다시 설치 | **서버 주소 설정**(여러 서버 저장, 집 안 LAN 주소와 외부 주소를 차례로 시도) |
| 새 버전 알림 | **자동 업데이트** |
| 작업 표시줄 미리보기의 버튼 | **썸네일 툴바**(이전·재생·다음), 작업 표시줄 진행 막대 |
| 창이 가려지면 브라우저가 타이머를 늦춤 | **백그라운드 제한 끔**(`backgroundThrottling: false`) |

키보드 미디어 키(⏯)와 Windows 미디어 오버레이(SMTC)는 웹 앱의 Media Session을 Electron(크로미움)이 그대로 연결하므로 따로 만들지 않는다(확인 항목에 포함).

## 2. 방식 결정

### Electron을 고른 이유
| 항목 | Electron |
|---|---|
| 엔진 | 크로미움 고정 버전을 앱에 포함 → PC마다 다른 브라우저·WebView 차이가 없다. 지금까지 크롬에서 확인한 재생·EQ·스와이프·라디오가 그대로 동작한다 |
| 네이티브 기능 | Tray, globalShortcut, 썸네일 툴바, 로그인 시 실행, 단일 실행, 알림, 자동 업데이트(electron-updater)가 모두 기본 제공 |
| 개발 언어 | 전부 TypeScript(웹 앱과 같은 언어). Rust 등 새 언어 불필요 |
| 단점 | 설치 파일 약 80~100MB, 메모리 약 200~300MB (Tauri안보다 큼) |

### 화면을 어디서 가져올까 — 서버에서 불러오기(결정)
| 안 | 내용 | 판단 |
|---|---|---|
| **A. 서버의 웹 화면을 앱 창에 불러오기** | 앱 창이 `https://NAS주소/`를 연다. 앱은 창·트레이·단축키 같은 Windows 기능만 맡는다 | **채택.** 서버·웹 앱을 그대로 쓴다는 원칙에 맞고, 서버를 업데이트하면 앱 화면도 같이 바뀌어 버전이 어긋나지 않는다. 로그인 쿠키·다운로드·서비스 워커도 지금 방식 그대로 |
| B. 웹 앱 빌드를 앱 안에 넣고 API만 서버로 | 화면은 앱에서, 데이터만 서버에서 | 쓰지 않음. 서버에 CORS·교차 출처 쿠키(SameSite=None) 변경이 필요하고, 앱과 서버 버전이 어긋나면 깨진다 |

## 3. 구조

```
┌──────────────── muzplayer for Windows (Electron) ────────────────┐
│ main 프로세스 (Node, TypeScript)                                   │
│  ├ 서버 목록·설정 저장 (%APPDATA%\muzplayer\settings.json)          │
│  ├ 단일 실행 잠금, 창 크기·위치 기억                                  │
│  ├ Tray + 메뉴, globalShortcut, 썸네일 툴바, 작업 표시줄 진행 막대     │
│  ├ 자동 시작(app.setLoginItemSettings), 알림                         │
│  ├ 자동 업데이트(electron-updater)                                   │
│  └ 보안: 서버 출처 밖으로의 이동 차단, 외부 링크는 기본 브라우저로       │
│                                                                     │
│ 연결 화면 (앱에 포함된 작은 페이지)                                    │
│  └ 서버 주소 입력·선택, 연결 확인(/api/v1/config의 version 표시)       │
│                                                                     │
│ 메인 창 BrowserWindow ── https://NAS주소/  (지금 웹 앱 그대로)         │
│  └ preload(contextBridge): window.muzNative                          │
│        웹 → 앱: 지금 곡·재생 상태·진행률                              │
│        앱 → 웹: toggle / next / prev / open                          │
│ 미니 창 BrowserWindow ── 같은 서버의 /mini (2단계)                     │
└─────────────────────────────────────────────────────────────────────┘
            │ HTTPS(외부) 또는 HTTP(LAN)
            ▼
     NAS: muzplayer 컨테이너 (변경 없음)
```

- **세션:** `session.fromPartition('persist:muzplayer')`로 로그인 쿠키·서비스 워커·다운로드 캐시를 앱 전용으로 영구 보관한다. 크롬과 로그인이 따로다.
- **앱 ↔ 웹 연결:** preload가 `window.muzNative`(contextIsolation 유지)를 만든다. 웹 앱은 이것이 있으면(앱 안에서 열림) 재생 상태를 보내고 명령을 받는다. 웹 쪽 처리는 원격 제어(`stores/remote.ts`)의 명령 이름(toggle·next·prev)을 그대로 써서 짧게 만든다. **`window.muzNative`가 없으면 아무것도 하지 않으므로 브라우저·PWA 사용에는 영향이 없다.**
- **보안 설정:** `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. 창 이동은 등록한 서버 출처만 허용, 새 창·외부 링크(유튜브 등)는 기본 브라우저로 연다.
- **자체 서명 인증서(LAN의 https):** 처음 볼 때 "이 서버의 인증서를 신뢰" 확인을 받고, 그 지문만 저장해 허용한다(전부 허용하지 않음).
- **연결 실패:** 서버에 닿지 않으면 연결 화면에 "연결할 수 없음 · 다시 시도 · 다른 주소"를 보여 준다. 저장된 주소가 여러 개면(LAN → 외부) 차례로 시도한다.

## 4. 기능과 단계

### 1단계 — 쓸 수 있는 앱 (MVP)
1. 연결 화면: 서버 주소 입력·저장(여러 개), 연결 확인, 마지막 서버로 바로 열기.
2. 메인 창: 서버 웹 앱 열기, 창 크기·위치 기억, 단일 실행(두 번 열면 기존 창을 앞으로).
3. 트레이: 닫기 = 트레이로 숨김(설정에서 "닫으면 종료" 선택 가능), 메뉴, 툴팁에 지금 곡.
4. 전역 단축키(기본값·변경·끄기).
5. 미디어 키·SMTC 동작 확인.
6. 앱 메뉴: 서버 바꾸기, 새로고침, 개발자 도구(숨김 메뉴), 정보(앱·서버 버전).
7. 설치 파일: NSIS 설치형 `.exe`(사용자 폴더 설치, 관리자 권한 불필요) + 휴대용 `.zip`.

### 2단계 — 편의
1. 미니 플레이어 창(항상 위). 서버에 `/mini` 화면 추가(선택 사항, 5장).
2. 자동 시작(트레이로), 썸네일 툴바, 작업 표시줄 진행 막대, 곡이 바뀔 때 알림(끄기 가능).
3. 자동 업데이트: Gitea 릴리스(또는 서버가 내려주는 주소)의 `latest.yml`을 electron-updater가 확인해 받아 설치.
4. ARM64 빌드.

### 3단계 — 필요할 때
1. 다운로드한 곡을 PC 폴더에 저장(지금은 앱 세션 저장소).
2. "지금 듣는 곡"을 Discord 등에 표시.

## 5. 서버(muzplayer) 쪽

**필수 변경 없음.** 아래는 앱 기능을 살리기 위한 선택 사항이고, 웹 앱에 넣어도 브라우저 사용에는 영향이 없다.

| 추가 | 내용 | 단계 |
|---|---|---|
| `src/native.ts` | `window.muzNative`가 있을 때만: 재생 상태를 앱에 보내고 앱 명령을 player에 전달 | 1 |
| 앱 감지 | 앱 안에서는 "앱 설치(PWA)" 안내를 숨기고 "Windows 앱" 정보 표시 | 1 |
| `/mini` 화면 | 재생 바만 있는 작은 화면 | 2 |
| 다운로드 안내 | 설정 → 앱 설치에 "Windows 앱 받기" 링크 | 2 |

이 추가 없이도 1단계의 트레이·단축키 중 **재생 명령은 동작**한다(앱이 페이지의 미디어 세션 동작을 대신 눌러 줄 수 있음). 다만 트레이 툴팁의 곡 이름·진행 막대는 `native.ts`가 있어야 정확하다.

## 6. 개발·빌드·배포

- **저장소:** Gitea에 `muzplayer-windows`를 새로 만든다(폴더명과 같게). 웹 앱과 릴리스 주기를 따로 간다.
- **구성:** Electron + TypeScript, electron-vite(빌드), electron-builder(설치 파일), electron-updater(업데이트), electron-store(설정).
- **빌드 환경:** 이 서버(리눅스)에서 `electronuserland/builder:wine` 도커 이미지로 Windows용 NSIS 설치 파일을 만든다. 안 되면 Windows PC에서 `npm run dist`.
- **버전:** `0.1.0`부터. 앱이 필요로 하는 서버 최소 버전을 적어 두고, 낮으면 "서버를 업데이트하세요"를 띄운다.
- **배포:** 설치 파일·`latest.yml`을 Gitea 릴리스에 올린다. 자동 업데이트도 여기를 본다.
- **코드 서명:** 하지 않는다. 처음 설치할 때 SmartScreen "알 수 없는 게시자" 경고가 뜨고 "추가 정보 → 실행"으로 설치한다. 가족용으로는 충분하며, 필요해지면 서명 인증서를 산다.

## 7. 확인 항목 (Windows PC에서, 사용자 확인 필요)

| 항목 | 확인 방법 |
|---|---|
| 재생·탐색·라디오·손상 MP3 변환 재생 | 웹에서 하던 그대로 |
| 미디어 키·SMTC | 키보드 ⏯, 작업 표시줄의 미디어 카드 |
| 트레이로 숨긴 채 1시간 재생 | 소리가 끊기지 않는지 |
| 절전 복귀 후 재생·로그인 유지 | 노트북 덮개 닫았다 열기 |
| LAN http 주소와 외부 https 주소 | 둘 다 저장하고 집 밖에서 실행 |
| 서버가 꺼진 상태에서 실행 | 연결 화면 안내, 다운로드한 곡 재생 |
| 자동 업데이트 | 0.1.0 설치 → 0.1.1로 |
| 화면 배율 150%·200%, 다크 테마 | 트레이 아이콘·창 선명도 |

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 리눅스에서 Windows 빌드 실패 | wine 빌더 이미지 → 안 되면 Windows PC에서 빌드 |
| 크로미움 보안 업데이트를 따라가야 함 | Electron 메이저 업데이트를 분기마다 반영(자동 업데이트로 배포) |
| 자체 서명 https | 인증서 지문을 사용자 확인 후 저장 |
| SmartScreen 경고 | 설치 안내 문서, 필요하면 서명 인증서 |
| 웹 앱 변경으로 연결 코드가 깨짐 | `native.ts`를 웹 앱 저장소에 두고, 스모크 테스트에 `window.muzNative` 모의 검사 추가 |
| 설치 파일 크기(약 90MB) | 업데이트는 차등 다운로드(electron-builder의 blockmap)로 줄인다 |
