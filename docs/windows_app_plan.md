# Windows 앱 계획서

- **작성일:** 2026-11-01
- **상태:** 계획 (구현 전)
- **대상:** Windows 10 21H2 이상 / Windows 11, x64 (ARM64는 2단계)
- **기준 버전:** muzplayer 0.16.x (웹 앱·서버)

## 1. 목표

NAS의 muzplayer를 **PC에 설치하는 앱**으로 쓰게 한다. 지금도 크롬·엣지에서 "앱 설치"(PWA)는 되지만, 브라우저가 해 주지 못하는 것들이 있다.

| 지금 PWA로 안 되는 것 | Windows 앱에서 |
|---|---|
| 창을 닫으면 음악이 멈춤 | **트레이로 숨기고 계속 재생**, 트레이 메뉴(재생·일시정지·다음·종료) |
| 다른 앱을 쓰는 중 단축키 | **전역 단축키**(Ctrl+Alt+Space 재생/일시정지, Ctrl+Alt+→/← 다음/이전) |
| 작은 창으로 띄워 두기 | **미니 플레이어**(항상 위, 커버·제목·컨트롤만) |
| Windows 시작 시 실행 | **자동 시작**(트레이로) |
| 서버 주소가 바뀌면 다시 설치 | **서버 주소 설정 화면**(여러 서버 저장, LAN/외부 주소 자동 선택) |
| 새 버전 알림 | **자동 업데이트**(서버가 새 설치 파일을 알려 줌) |
| 작업 표시줄 미리보기의 재생 버튼 | **썸네일 툴바**(이전·재생·다음) |

미디어 키(키보드의 ⏯)와 Windows 미디어 오버레이(SMTC)는 웹 앱의 Media Session이 WebView2에서도 그대로 동작하므로 따로 만들 필요가 없다(확인 항목에 포함).

**만들지 않는 것:** 음악 파일을 PC에 두고 재생하는 로컬 플레이어, 별도 UI 재작성. 화면은 지금 웹 앱을 그대로 쓴다.

## 2. 방식 비교와 결정

| 방식 | 설치 파일 | 메모리 | 네이티브 기능 | 비고 |
|---|---|---|---|---|
| PWA(현재) | 없음 | 브라우저와 공유 | 거의 없음 | 위 표의 것들을 못 함 |
| **Tauri 2 + WebView2** | **약 5~10MB** | 약 80~150MB | 트레이·단축키·업데이트·창 제어 | WebView2는 Windows 10/11에 기본 포함(엣지와 같은 엔진) |
| Electron | 약 80~120MB | 약 200~300MB | 모두 가능 | 크롬을 통째로 넣음, 무거움 |
| .NET MAUI / WinUI | 중간 | 중간 | 모두 가능 | UI를 새로 만들어야 함 |

**결정: Tauri 2.** 웹 앱을 그대로 쓰면서 가볍고, 필요한 네이티브 기능(트레이, 전역 단축키, 자동 시작, 업데이트, 단일 실행)이 공식 플러그인으로 있다. 이 서버의 웹 화면과 같은 엔진(Chromium 계열)이라 지금까지 확인한 재생·EQ·스와이프가 그대로 동작할 가능성이 높다.

## 3. 구조

```
┌───────────── Windows 앱 (Tauri) ─────────────┐
│  시작 화면(앱에 포함)                          │
│   └ 서버 주소 입력·선택·연결 확인              │
│  메인 창 = WebView2                            │
│   └ https://NAS주소/  ← 지금 웹 앱을 그대로 불러옴│
│  네이티브 쪽(Rust)                             │
│   ├ 트레이 아이콘·메뉴                         │
│   ├ 전역 단축키 → 웹 앱의 player에 명령 전달    │
│   ├ 미니 플레이어 창(같은 서버의 /mini 화면)     │
│   ├ 자동 시작, 단일 실행, 창 위치 기억           │
│   └ 업데이트 확인(서버의 /api/v1/app/windows)    │
└────────────────────────────────────────────────┘
```

- **화면은 서버에서 불러온다(설치본에 넣지 않는다).** 서버를 업데이트하면 앱 화면도 같이 바뀌어 버전이 어긋나지 않는다. 로그인 쿠키·오프라인 캐시도 지금 웹 앱 방식 그대로 쓴다.
- **앱 ↔ 웹 연결:** 앱이 페이지에 작은 스크립트를 넣어 `window.muzNative`를 만든다. 웹 앱은 이것이 있으면(앱 안에서 열림) 앱 전용 기능을 켠다.
  - 웹 → 앱: 지금 곡 정보·재생 상태(트레이 툴팁·썸네일 툴바·미니 창 갱신)
  - 앱 → 웹: 단축키·트레이 메뉴 명령(`toggle`, `next`, `prev`, `open`)
  - 지금 있는 원격 제어(`stores/remote.ts`)의 명령 이름을 그대로 써서 웹 쪽 처리 코드를 재사용한다.
- **오프라인일 때:** 서버에 연결할 수 없으면 시작 화면에서 "연결할 수 없음 + 다시 시도 + 주소 바꾸기"를 보여 준다. 이미 받아 둔 다운로드는 웹 앱의 서비스 워커가 처리하므로 그대로 들을 수 있다(확인 항목).

## 4. 기능 목록과 단계

### 1단계 — 쓸 수 있는 앱 (MVP)
1. 서버 주소 화면: 주소 입력, 연결 확인(`/api/v1/config`의 version 표시), 여러 서버 저장, 마지막 서버로 바로 열기.
2. 메인 창: 웹 앱 불러오기, 창 크기·위치 기억, 단일 실행(두 번 열면 기존 창을 앞으로).
3. 트레이: 창 닫기 = 트레이로 숨김(설정으로 "닫으면 종료" 선택), 메뉴(열기·재생/일시정지·다음·이전·종료), 툴팁에 지금 곡.
4. 전역 단축키(기본값, 설정에서 변경·끄기).
5. 미디어 키·SMTC 동작 확인. 안 되면 Rust 쪽에서 SMTC를 직접 연결.
6. 설치 파일(NSIS 설치형 `.exe`, 사용자 폴더 설치라 관리자 권한 불필요).

### 2단계 — 편의
1. 미니 플레이어 창(항상 위, 300×110 정도, 커버 색 배경). 서버에 `/mini` 화면 추가.
2. 자동 시작(트레이로), 작업 표시줄 썸네일 툴바, 곡이 바뀔 때 알림(끄기 가능).
3. 자동 업데이트: 서버 `/api/v1/app/windows`가 최신 버전·설치 파일 주소·서명을 알려 주고, Tauri updater가 받아 설치.
4. ARM64 빌드.

### 3단계 — 선택
1. 오프라인 다운로드를 PC 폴더에 저장(지금은 브라우저 저장소).
2. Discord 등 "지금 듣는 곡" 표시(원하면).
3. 라이브러리 폴더를 직접 고르는 "PC 음악 서버" 모드는 하지 않음(범위 밖).

## 5. 서버(muzplayer) 쪽 변경

| 변경 | 내용 | 단계 |
|---|---|---|
| 앱 감지 | `window.muzNative`가 있으면 PWA 설치 안내 숨기기, 앱 설정 메뉴 보이기 | 1 |
| 앱 연결 코드 | `src/native.ts`: 재생 상태를 앱에 보내고, 앱 명령을 player에 전달 | 1 |
| 미니 화면 | 라우트 `/mini`(로그인 필요, 재생 바만 있는 작은 화면) | 2 |
| 업데이트 정보 | `GET /api/v1/app/windows` → `{version, url, signature, notes}`. 설치 파일은 Gitea 릴리스 또는 서버 `DATA_DIR/app/` | 2 |
| 다운로드 안내 | 설정 → 앱 설치에 "Windows 앱 받기" 링크 | 2 |

CORS·쿠키 설정은 바꿀 필요가 없다(화면을 서버 주소에서 그대로 불러오므로 같은 출처).

## 6. 빌드·배포

- **저장소:** Gitea에 `muzplayer-windows`를 새로 만든다(폴더명과 같게). 웹 앱 저장소와 분리해 릴리스 주기를 따로 가져간다.
- **빌드 환경:** 이 서버(리눅스)에서 `cargo-xwin` + NSIS로 Windows 설치 파일을 교차 빌드한다(Tauri 2가 지원, 단 실험적). 문제가 있으면 Windows PC에서 `npm run tauri build`. Gitea Actions 러너는 리눅스라 교차 빌드 방식으로 맞춘다.
- **버전:** `0.1.0`부터. 앱이 지원하는 서버 최소 버전을 앱에 적어 두고, 낮으면 "서버를 업데이트하세요"를 띄운다.
- **코드 서명:** 서명하지 않으면 처음 설치할 때 SmartScreen "알 수 없는 게시자" 경고가 뜬다.
  - 가족용이면 "추가 정보 → 실행"으로 충분하다.
  - 경고를 없애려면 코드 서명 인증서(연 수십만 원대)가 필요하다 → 지금은 하지 않는다.
- **업데이트 서명:** Tauri updater용 서명 키는 따로 만들어 `~/.muzplayer-windows/updater.key`(600 권한)에 두고, 대화·저장소에 넣지 않는다.

## 7. 확인 항목 (실기기)

| 항목 | 확인 방법 |
|---|---|
| 재생·탐색·변환 스트림(손상 MP3·WMA)·라디오 | 웹 스모크와 같은 화면을 앱에서 |
| 미디어 키·SMTC(작업 표시줄 위 미디어 카드) | 키보드 ⏯, Win+A 미디어 카드 |
| 창을 숨긴 채 30분 재생 | WebView2가 숨은 창을 멈추지 않는지(백그라운드 제한) |
| 절전 복귀 후 재생·로그인 유지 | 노트북 덮개 닫았다 열기 |
| http(LAN IP)·https 주소 둘 다 | 자체 서명 인증서 경고 처리 포함 |
| 오프라인 시작 | 서버 꺼진 상태에서 실행 → 안내 화면, 다운로드한 곡 재생 |
| 업데이트 | 0.1.0 설치 → 0.1.1 자동 업데이트 |
| 고해상도(150%·200%)·다크 테마 | 트레이 아이콘·미니 창 선명도 |

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| WebView2가 숨긴 창의 타이머를 늦춰 재생이 멈춤 | 오디오 재생 중엔 보통 유지됨. 문제면 숨길 때 창을 최소화 대신 화면 밖으로 옮기거나 `--disable-background-timer-throttling` 옵션 |
| 교차 빌드 실패 | Windows PC에서 직접 빌드로 전환 |
| 자체 서명 https(LAN) | 서버 주소 화면에서 "이 인증서 신뢰" 선택을 저장 |
| SmartScreen 경고 | 안내 문서 제공, 필요하면 서명 인증서 |
| 웹 앱 변경으로 앱 연결 코드가 깨짐 | `native.ts`를 웹 앱 안에 두고 스모크 테스트에 `window.muzNative` 모의 검사 추가 |
