# 뮤직 영상 → 음원 추출 계획서

- 작성: 2026-11-13 (muzplayer 0.66.0 기준)
- 목표: 뮤직 영상(YouTube 링크 또는 NAS의 로컬 영상)에서 **mp3나 m4a 음원을 뽑고**, AI와 벅스·멜론 정보로 **태그와 앨범 커버를 자동으로 붙여**, 라이브러리의 새 분류 **"추출 음원"**에 보여 준다.
- 참고: [sruinz/Video-Download-to-NAS](https://github.com/sruinz/Video-Download-to-NAS) (MIT). yt-dlp로 받고, ffmpeg 후처리(`FFmpegExtractAudio`, `preferredcodec: mp3|m4a`, 192kbps)로 음원만 남긴다. YouTube 서명 해독에 JavaScript 실행기(deno)를 함께 설치한다.

## 0. 먼저 정할 것 (확인 필요)

| 항목 | 제안 |
|---|---|
| 기본 형식 | **m4a** (YouTube 음성은 원래 AAC라 다시 인코딩하지 않아 음질 손실이 없음). mp3는 선택 |
| 저장 폴더 | NAS의 `MUZPLAYER_DIR/library/music/추출 음원` (2.1) |
| 태그 적용 | **자동**: 추출 직후 AI·벅스가 찾은 태그를 바로 넣고, 나중에 고칠 수 있게 함 |
| 쓸 수 있는 사람 | 관리자만 (설정에서 일반 사용자에게도 열 수 있음) |

> **저작권·약관 주의:** YouTube 약관은 서비스가 허락한 경우 외의 다운로드를 금지합니다. 이 기능은 개인 NAS에서 본인이 쓰는 용도로, 권리가 있거나 허락된 영상에만 쓰도록 안내합니다. 관리자 설정에서 **기본은 꺼짐**으로 두고, 켤 때 이 안내를 보여 줍니다. 로컬 영상(NAS 파일)에서 뽑는 기능은 이와 별개로 항상 쓸 수 있습니다.

## 1. 지금 앱에서 이미 있는 것

| 필요한 것 | 지금 상태 |
|---|---|
| 뮤직 영상 목록 | YouTube 링크 영상 + NAS 로컬 영상(`videos` 표). 곡·앨범과 연결될 수 있음 |
| ffmpeg | 앱 이미지에 **최소 구성**으로 들어 있음(mp3 인코딩 가능). m4a로 담는 기능(mp4 컨테이너, AAC 인코더)과 YouTube 음성(Opus·AAC) 디코딩은 추가 필요 |
| AI | Gemini·OpenAI 키 설정, JSON 형식 응답(AI 플레이리스트에서 사용 중) |
| 벅스·멜론 | 앨범 설명·별점 조회, 벅스 곡·아티스트 검색, 가사 조회 |
| 태그 | mutagen으로 읽기만 함 (라이브러리는 읽기 전용으로 마운트됨) |
| 분류 | 폴더 종류(앨범·컴필레이션·차트·테마·제외)로 라이브러리 분류 |

## 2. 구조

```
[뮤직 영상] ──"음원으로 추출"──▶ 추출 작업(백그라운드, 한 번에 하나)
                                  │ 1. 받기: YouTube → yt-dlp (음성만) / 로컬 → ffmpeg
                                  │ 2. 변환: m4a(그대로 담기) 또는 mp3(192~320kbps)
                                  │ 3. 정보 찾기: 연결된 곡 → 벅스 검색 → AI 정리
                                  │ 4. 커버: 벅스·멜론 앨범 커버 → YouTube 썸네일(정사각 자르기)
                                  │ 5. 태그·커버·가사를 파일에 쓰기 (mutagen)
                                  ▼
                 library/music/추출 음원/<아티스트>/<앨범>/<번호 제목>.m4a
                                  │ 6. 그 폴더만 스캔
                                  ▼
                 라이브러리 → 앨범 → 분류 "추출 음원"
```

### 2.1 저장 위치 (라이브러리는 읽기 전용)
- 지금 라이브러리는 `library:/library:ro`로 마운트되어 앱이 쓸 수 없다. 추출 음원 폴더 하나만 **쓰기 가능하게 겹쳐 마운트**한다.
  ```yaml
  - ${MUZPLAYER_DIR}/library:/library:ro
  - ${MUZPLAYER_DIR}/library/music/추출 음원:/library/music/추출 음원   # 쓰기 가능
  ```
- 이렇게 하면 스캐너는 지금처럼 `library/music`만 보면 되고, 이 폴더는 하나의 최상위 폴더로 들어온다.
- 관리자 → 폴더 종류에 **"추출 음원"** 종류를 추가하고, 이 폴더에 자동으로 지정한다(`library_folders.kind = 'extracted'`).
- 마운트가 없으면 추출 버튼 대신 "docker-compose에 추출 폴더를 추가하세요" 안내를 보여 준다. 새 docker-compose.yml에는 기본으로 넣는다.

### 2.2 받기와 변환
- **YouTube**: `yt-dlp`(파이썬 패키지)와 **deno**(서명 해독용)를 이미지에 넣는다.
  - 음성 트랙만 받는다(`bestaudio`, 보통 AAC 128k 또는 Opus 160k). 영상은 받지 않는다.
  - m4a: AAC 음성이면 다시 인코딩하지 않고 그대로 담는다. Opus뿐이면 AAC 256k로 변환한다.
  - mp3: libmp3lame로 V0 또는 320k(설정)로 변환한다.
- **로컬 영상**: yt-dlp 없이 ffmpeg로 바로 뽑는다(mp4·mkv의 AAC는 그대로, 그 밖은 변환).
- ffmpeg 빌드에 추가할 것: `aac` 인코더, `ipod`(m4a) 먹서, `opus`·`libopus` 디코더, `aac_adtstoasc` 비트스트림 필터, `webm` 디먹서. 늘어나는 크기는 수 MB다.
- yt-dlp는 YouTube가 바뀔 때마다 자주 고쳐진다. 그래서 두 가지를 둔다.
  - 이미지 릴리즈마다 최신으로 고정해 넣는다.
  - 관리자 화면에 **"yt-dlp 업데이트"** 버튼을 둔다. `DATA_DIR/pylib`에 새 버전을 설치하고 그쪽을 먼저 쓴다.
- 이미지 크기: deno 약 +90MB, yt-dlp 약 +10MB.

### 2.3 태그 찾기 (AI 연동, 자동)
정확한 순서대로 시도하고, 앞에서 확정되면 뒤는 건너뛴다.
1. **영상이 곡과 연결되어 있으면**(뮤직 영상 등록 때 자동 연결된 곡): 그 곡의 태그(제목, 아티스트, 앨범, 연도, 장르, 트랙 번호)와 앨범 커버를 그대로 쓴다.
2. **AI 정리**: 영상 제목·채널명·설명·길이를 AI에 보내고, JSON으로 다음을 받는다.
   - `artist`, `title`, `featured`, `album`(모르면 빈칸), `year`, `genre`, `version`(Live, Acoustic, Remix 등), `is_music`(음악이 아니면 false), `confidence`
   - 예: `아이유(IU) - 밤편지 [MV]` → 아티스트 아이유, 제목 밤편지, 버전 없음
   - `[MV]`, `(Official Video)`, `| 4K` 같은 꾸밈말은 지운다. 라이브·커버 영상은 `version`으로 남긴다.
3. **벅스로 확인**: AI가 찾은 "아티스트 + 제목"으로 벅스 곡을 검색해 하나로 맞으면 공식 정보로 덮는다(앨범, 발매일, 트랙 번호, 장르, 앨범 커버, 벅스 아티스트 이름). 멜론 검색은 보조로 쓴다.
4. **AI 키가 없으면**: "아티스트 - 제목" 규칙으로 나눈 뒤 벅스 검색만 한다.
5. **가사**: 기존 가사 조회(알송·벅스·LRCLIB)로 찾아 파일에 넣는다(싱크 가사면 LRC).

- 확인되지 않은 정보는 비워 둔다. 지어내지 않는다.
- AI 응답이 확신 낮음(`confidence` < 0.6)이거나 `is_music=false`이면 결과에 **"확인 필요"** 표시를 붙인다.

### 2.4 앨범 커버
1. 벅스·멜론에서 찾은 앨범의 공식 커버(1000px)
2. 없으면 YouTube 썸네일(최대 해상도)을 정사각형으로 잘라 쓴다. 가운데를 자르되, 위아래 검은 띠는 먼저 잘라 낸다.
3. 둘 다 없으면 AI 이미지 생성으로 커버를 만든다(기존 AI 배너 기능 재사용, 선택 사항).
- 커버는 파일에 넣고(`APIC` / `covr`), 같은 폴더에 `cover.jpg`로도 둔다.

### 2.5 파일 이름과 폴더
- `추출 음원/<앨범 아티스트>/<앨범>/<두 자리 번호> <제목>.m4a`
- 앨범을 모르면 `추출 음원/<아티스트>/싱글/<제목>.m4a`
- 같은 곡을 다시 뽑으면 덮어쓸지 묻는다. 원본 영상 주소는 태그(`comment`, `purl`)에 남긴다.

## 3. 화면

### 3.1 뮤직 영상
- 영상 카드의 ⋯ 메뉴와 영상 플레이어에 **"음원으로 추출"**을 둔다.
  - 형식(m4a/mp3)과 음질을 고르는 짧은 창을 띄운다. 기본값은 기억한다.
  - ~~영상 플레이리스트에서 "전체 추출"~~ — 하지 않기로 함(2026-11-13).
- 이미 추출한 영상에는 ♪ 표시를 하고, 누르면 그 곡으로 간다.

### 3.2 추출 작업 목록
- 뮤직 영상 화면 위쪽(또는 관리자 화면)에 **"추출 작업"**을 둔다. 대기, 받는 중(%), 정보 찾는 중, 완료, 실패와 원인이 보인다.
- 완료된 항목에는 찾은 태그와 커버가 미리 보이고 "고치기"를 누를 수 있다.
- 실패 원인 예: 영상이 비공개됨, 나이 제한, 지역 제한, yt-dlp 버전이 오래됨 → "yt-dlp 업데이트" 안내.

### 3.3 태그 고치기
- 추출 음원의 곡·앨범 화면에 **"태그 편집"**(관리자)을 둔다.
  - 제목, 아티스트, 앨범, 연도, 장르, 트랙 번호, 커버(벅스 후보·직접 올리기)를 고친다.
  - "AI로 다시 찾기"를 누르면 2.3을 다시 돈다.
- 파일에 바로 다시 쓰고, 그 폴더만 다시 스캔한다. 추출 음원 폴더만 쓰기가 가능하므로 다른 라이브러리 파일은 절대 건드리지 않는다.

### 3.4 라이브러리
- 앨범 목록의 분류 칩에 **"추출 음원"**을 추가한다(정규·비정규·컴필레이션·OST 옆).
- 곡 목록과 검색에서 추출 음원 곡에는 작은 표시(▶ 영상에서)를 붙인다.
- 홈 화면에는 "최근 추출" 줄을 둔다(선택).

## 6. 확인 방법
- 표본 영상 30개로 정확도를 본다. 공식 MV, 라이브, 커버 영상, 제목이 영어/한글/일본어인 것, 피처링, 채널명이 아티스트가 아닌 것을 섞는다.
  - 아티스트·제목 정확도와 앨범·커버가 맞는 비율을 기록한다.
- m4a는 다시 인코딩하지 않았는지(ffprobe로 코덱·비트레이트), mp3는 설정한 음질인지 확인한다.
- 만든 파일을 다른 플레이어(iPhone 파일 앱, foobar2000)에서 열어 태그·커버·가사가 보이는지 본다.
- 스캔 뒤 "추출 음원" 분류에 나오는지, 다시 뽑기·삭제·태그 편집 후 스캔에 바르게 반영되는지 본다.
- 실패 상황을 시험한다: 비공개 영상, 없는 주소, 인터넷이 안 되는 상태, 추출 폴더 마운트가 없는 상태.
- 스모크 테스트에 로컬 영상 추출 1건(인터넷 없이 가능)을 넣는다.

## 7. 위험과 대응
| 위험 | 대응 |
|---|---|
| YouTube 변경으로 받기 실패 | yt-dlp 업데이트 버튼, 실패 원인 안내, 릴리즈마다 최신 yt-dlp |
| 저작권·약관 | 기본 꺼짐, 켤 때 안내, 관리자만, 개인 NAS 용도 |
| AI가 틀린 태그를 붙임 | 벅스로 확인된 것만 공식값 사용, 확신 낮으면 '확인 필요', 태그 편집 창 |
| 라이브러리 파일을 잘못 덮어씀 | 쓰기는 추출 음원 폴더 안에서만(경로 검사), 라이브러리는 계속 읽기 전용 |
| 이미지가 커짐(deno) | 약 +100MB. 필요하면 "추출 기능 포함" 이미지를 따로 두는 방안도 가능 |
| NAS CPU 부담 | 작업은 한 번에 하나, 낮은 우선순위(nice)로 실행 |
