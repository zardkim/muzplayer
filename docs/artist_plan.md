# 아티스트 이름·중복·정렬 개선 계획서 (벅스 기준)

- 작성: 2026-11-09 (muzplayer 0.57.0 개발본 기준: 아티스트 다른 이름 조회 포함) · 0.58.0 단계 구현 (2026-11-09)
- 목표:
  1. 아티스트 이름을 음원 태그 그대로가 아니라 **벅스의 아티스트 이름**으로 보여 준다.
  2. 그룹과 멤버(개인)를 구분하고, 한 곡의 여러 아티스트를 각각의 아티스트로 다룬다.
  3. 영어·한글·일본어 이름이 섞여도 정렬, 중복 찾기, 합치기가 맞게 되게 한다.

## 1. 지금 상태와 문제

| 항목 | 지금 | 문제 |
|---|---|---|
| 아티스트 만들기 | 태그의 아티스트 값 문자열 하나가 아티스트 하나 (`scanner._Cache.artist`) | "아이유", "IU", "아이유 (IU)"가 각각 다른 아티스트. "윤슬 feat. Marlow"가 통째로 한 아티스트 |
| 여러 아티스트 | 태그 값 여러 개를 " / "로 이어 `artist_text`에 저장. **첫 번째만** 아티스트로 연결 (`artist_id`) | 피처링·콜라보 아티스트의 페이지에 그 곡이 안 나옴. "A, B", "A & B", "A x B" 한 문자열은 나누지 않음 |
| 표시 | 태그 문자열 그대로 | 같은 가수가 앨범마다 다른 이름으로 보임 |
| 중복 찾기 (`merge.duplicates`) | 대소문자·띄어쓰기·기호를 뺀 이름, 괄호 안팎 이름이 같으면 같은 그룹 | **"써니 (소녀시대)"가 "소녀시대"와 같은 아티스트로 묶임**(괄호가 다른 이름이 아니라 소속 그룹). 그룹과 개인을 구분하지 못함 |
| 정렬 | `sort_name = 이름 소문자`, 글자 코드 순 | 영어 → 한글 → 일본어 순으로 흩어짐. "The Beatles"가 T에. 한글 이름 해외 가수(머라이어 캐리)는 M에만 |

## 2. 벅스에서 얻을 수 있는 것 (2026-11-09 실제 조회로 확인)

| 정보 | 예 | 쓰는 곳 |
|---|---|---|
| 아티스트 id, 이름(다른 이름) | `소녀시대 (GIRLS' GENERATION)`, `Kenshi Yonezu(켄시 요네즈/米津 玄師)`, `Mariah Carey(머라이어 캐리)` | 표시 이름, 다른 이름, 같은 아티스트 판정 |
| 유형 | 솔로 (여성) / 그룹 (여성) / 듀오 (혼성) | 그룹·개인 구분 |
| 멤버 (그룹 페이지) | 소녀시대 → 유리, Tiffany Young, 수영, 서현, 태연, 윤아, 효연, 써니 | 그룹 ↔ 멤버 연결, 중복 오판 방지 |
| 소속 활동 (개인 페이지) | 태연 → 소녀시대, 소녀시대-태티서, GOT the beat … | 같은 연결의 반대 방향 |
| 국적, 데뷔, 장르 | 대한민국, 2007, 발라드 | 아티스트 페이지 정보 |
| 앨범 수록곡의 아티스트 | 앨범 페이지의 곡마다 아티스트 링크 | 곡의 아티스트를 벅스 id로 연결 (가장 정확) |

주의할 점:
- 벅스는 콜라보를 **별도 아티스트**로 두기도 한다("이유 갓지(GOD G) 않은 이유(박명수, 아이유)"). 이런 프로젝트 아티스트는 괄호 안의 실제 아티스트들에게도 곡을 연결한다.
- 벅스에 없는 아티스트(인디, 직접 만든 음원, 동명이인으로 구분이 안 되는 경우)는 **태그 이름을 그대로** 쓴다. 벅스 연결은 덧붙이는 정보이고, 없으면 지금처럼 동작한다.

## 3. 바꿀 데이터 구조

| 테이블·컬럼 | 내용 |
|---|---|
| `artists.bugs_id` | 연결된 벅스 아티스트 (없으면 NULL). 같은 `bugs_id` = 같은 아티스트 |
| `artists.display_name` | 보여 줄 이름: 벅스 이름 > 관리자가 정한 이름 > 태그 이름. 기존 `name`은 "태그에서 처음 만난 이름"으로 남겨 스캔 연결에 쓴다 |
| `artists.kind` | solo / group / unknown (+ 성별·국적·데뷔는 `artists.info` JSON) |
| `artist_links` (새 테이블) | 그룹 ↔ 멤버 (`group_id`, `member_id`), 벅스의 멤버·소속 활동에서 |
| `track_artists` (새 테이블) | 곡 ↔ 아티스트 여러 명 (`track_id`, `artist_id`, `role`: main / feat, 순서). 지금의 `Track.artist_id`(대표 아티스트)는 목록 속도를 위해 그대로 둔다 |
| `artist_names` (새 테이블) | 태그에 적힌 이름 → 아티스트 (여러 명일 수 있음). 지금의 병합 기록(`name_aliases`)을 옮겨 담는다. 태그는 바꾸지 않는다(라이브러리는 읽기 전용) |
| `artists.sort_key` | 정렬용 키 (5장) |

`Track.artist_text`는 "곡에 보이는 아티스트 글자"로 남겨 두되, 벅스로 연결되면 연결된 아티스트들의 표시 이름으로 다시 만든다. 검색·스마트 플레이리스트가 이 글자를 쓰기 때문이다.

## 4. 이름 나누기와 벅스 연결

### 4.1 태그 문자열을 여러 아티스트로 나누기 (외부 조회 없이)
- 나누는 기호: `feat.` `ft.` `(Feat. …)` `with` `,` `&` `x`/`X` `;` ` / `
- **이름 자체에 기호가 든 아티스트는 나누지 않는다**("Earth, Wind & Fire", "Simon & Garfunkel", "Crosby, Stills, Nash & Young"). 순서: ① 문자열 전체가 이미 아는 아티스트(벅스 연결 또는 관리자 지정)면 그대로 ② 아니면 나눈 조각들이 각각 아는 아티스트일 때만 나눈다 ③ 모르면 `feat.`류만 나누고 나머지는 그대로 둔다.
- 괄호: "아이유 (IU)"처럼 두 이름이 같은 사람이면 다른 이름. "써니 (소녀시대)"처럼 괄호가 그룹이면 소속. 어느 쪽인지는 벅스 연결(유형·멤버)로 판단하고, 모르면 지금처럼 문자열 그대로 둔다.

### 4.2 벅스 연결 순서 (정확한 것부터)
1. **앨범 단위:** 앨범 설명 조회 때 이미 찾은 벅스 앨범(`description_source = bugs:<id>`)이 있으면 그 앨범 페이지의 수록곡 아티스트를 곡 번호·제목으로 맞춰 곡마다 연결한다. 요청 1~2번으로 앨범 하나가 끝난다.
2. **아티스트 검색:** 앨범으로 못 찾은 이름은 벅스 아티스트 검색에서 이름(또는 괄호 속 다른 이름)이 **정확히 같은** 후보만 받는다. 후보가 여럿이면 우리 라이브러리의 곡·앨범 제목이 그 아티스트의 곡 목록과 겹치는 쪽을 고른다. 고를 수 없으면 연결하지 않고 관리자 확인 목록에 올린다.
3. **아티스트 페이지:** 연결된 아티스트는 페이지를 한 번 읽어 유형·멤버·소속·국적을 저장한다(90일마다 다시).
- 스캔이 끝난 뒤 백그라운드에서 한 번에 정해진 양만 한다(앨범 설명·다른 이름 조회와 같은 방식). 요청 사이에 쉬고, 벅스가 응답하지 않으면 다음 스캔으로 미룬다.
- 0.57.0의 다른 이름 조회(MusicBrainz·Wikidata)는 그대로 쓰고, 벅스 이름의 괄호 속 이름도 다른 이름으로 넣는다.

## 5. 정렬 (영어·한글·일본어)

`sort_key`를 이렇게 만든다.
1. 앞의 관사 빼기: "The Beatles" → "Beatles", "A Tribe Called Quest" → "Tribe Called Quest". 화면에는 원래 이름을 보인다.
2. **정렬 기준 이름 고르기:** 설정 "아티스트 정렬"
   - **한글 우선(기본):** 한글 이름이 있으면(벅스의 한글 이름, 다른 이름 중 한글) 그 이름으로 가나다순. 머라이어 캐리는 ㅁ, 켄시 요네즈는 ㅋ. 한글 이름이 없으면 영문으로.
   - **표시 이름 그대로:** 지금처럼 보이는 이름 기준.
3. 묶음 순서: 한글(ㄱ~ㅎ) → 영문(A~Z) → 일본어·기타 문자 → 숫자·기호. 각 묶음 안에서 가나다·알파벳순(대소문자·전각 무시).
4. 아티스트 목록에 **색인 막대**(ㄱ ㄴ ㄷ … A B C … #)를 두어 바로 이동한다.

일본어 한자 이름은 읽는 법을 알 수 없어서, 벅스의 한글·영문 이름을 정렬에 쓴다. 벅스에 없으면 일본어 묶음에서 글자 순이다.

## 6. 중복 찾기와 합치기

### 6.1 같은 아티스트 판정 (믿을 수 있는 순서)
| 근거 | 처리 |
|---|---|
| 같은 `bugs_id` | **자동으로 합친다**(설정에서 끌 수 있음). 표시 이름은 벅스 이름 |
| 다른 이름이 겹침 (MusicBrainz·Wikidata·벅스 괄호 이름) | 합치기 **제안** |
| 정규화한 이름이 같음 (대소문자·띄어쓰기·기호·전각 무시) | 합치기 **제안** |
| 괄호 안팎 이름 | 벅스로 같은 사람임이 확인될 때만 제안. 확인이 안 되면 제안하지 않음 |

### 6.2 합치지 않는 경우 (오판 방지)
- 한쪽이 그룹이고 다른 쪽이 그 멤버(`artist_links`)인 경우: "소녀시대"와 "써니 (소녀시대)", "방탄소년단"과 "정국"
- 유형이 다른 경우(솔로 ↔ 그룹)
- 서로 다른 `bugs_id`로 연결된 경우(동명이인)
- 관리자가 "다른 아티스트"로 표시한 짝은 다시 제안하지 않는다(`artist_not_same` 기록)

### 6.3 관리자 화면 (합치기)
- 제안마다 **근거**를 보여 준다: "벅스 같은 아티스트", "다른 이름 일치: IU", "이름 표기만 다름"
- 각 후보에 유형 배지(솔로/그룹)와 벅스 이름, 곡 수
- "합치기", "다른 아티스트", 남길 이름 고르기(벅스 이름 / 태그 이름 / 직접 입력)
- 벅스 연결이 애매한 아티스트 목록: 후보 중 고르기 또는 "벅스에 없음"

## 7. 화면

- **아티스트 페이지:** 벅스 이름(큰 글씨), 다른 이름, 유형·국적·데뷔. 그룹이면 **멤버**(라이브러리에 있는 멤버는 링크), 개인이면 **소속 그룹**. 피처링·참여곡 섹션(곡의 대표 아티스트가 아니어도 `track_artists`로 연결된 곡)
- **곡 목록:** 아티스트가 여럿이면 각각 링크("박명수, 아이유" → 두 아티스트 페이지)
- **아티스트 목록:** 새 정렬, 색인 막대, 유형 필터(전체/솔로/그룹)
- **설정 → 화면:** "아티스트 이름: 벅스 기준 / 태그 그대로", "아티스트 정렬: 한글 우선 / 표시 이름"

## 9. 확인 방법

- **시험용 이름 목록** (개발 라이브러리에 태그로 넣어 단계마다 확인):
  - 같은 사람: 아이유 / IU / 아이유 (IU) / iu
  - 그룹과 멤버: 소녀시대 / 태연 / 써니 (소녀시대) / 소녀시대-태티서
  - 나누면 안 되는 이름: Earth, Wind & Fire / Simon & Garfunkel
  - 나눠야 하는 이름: 윤슬 feat. Marlow / 박명수, 아이유 / Zion.T x Crush
  - 콜라보 프로젝트: 이유 갓지(GOD G) 않은 이유(박명수, 아이유)
  - 다국어 정렬: The Beatles / 머라이어 캐리(Mariah Carey) / 米津玄師 / YOASOBI / 10cm / (G)I-DLE
  - 동명이인: Sunny / Wave
- **벅스 연결 정확도:** 실제 사이트로 표본 앨범 50개·아티스트 100명을 연결해 잘못 붙은 것을 센다. 기준: 잘못 연결 0건(애매하면 연결하지 않는 쪽).
- **속도:** 10만 곡 벤치로 아티스트 목록·곡 목록·검색 응답 시간이 지금(곡 검색 40ms, 아티스트 목록 캐시 4ms)과 비슷한지. `track_artists` 연결 재생성 시간.
- **업그레이드:** 이전 DB에서 새 이미지 시작(마이그레이션), 합치기 되돌리기(unmerge)가 새 구조에서도 되는지, 스마트 플레이리스트의 아티스트 조건이 그대로 맞는지.

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
